## 1. 重构背景与目标

| 项 | 内容 |
|---|---|
| 起因 | uni-app（ASCF）编译的元服务不支持任何广告 API（§14 已论证），接入鲸鸿动能的唯一途径是**原生 ArkTS 元服务**（Ads Kit 为系统级能力，仅限原生工程调用） |

| 形态 | 单 Ability、Stage 模型、`bundleType = atomicService`，单包 ≤2MB / 总包 ≤10MB |

## 4. 广告接入设计（核心）

### 4.1 准入（业务侧，与代码并行办）

按主文档 §14.2 执行：企业实名认证 → 开通商户服务 → 签《鲸鸿动能媒体服务协议》→ 创建媒体（APPID 已有）→ 创建展示位拿广告位 ID。

### 4.2 广告位规划（首版）

| 位置 | 广告形式 | 理由 |
|---|---|---|
| 列表页信息流（每 ~8 条插 1 条） | **原生广告**（大图/视频，`AdComponent`） | 与招工卡片形态最接近，干扰最低，eCPM 高于 Banner |
| 详情页底部固定区上方 | **Banner**（`AutoAdComponent`，自动轮播 30s+） | 用户停留时间最长的页面，实现最简单 |
| （二期可选）查看联系方式前 | **激励视频** | "看广告解锁电话"玩法，需业务确认是否改变现有免费联系逻辑，首版不做 |

### 4.3 技术要点

- **API**：`@kit.AdsKit` → `advertising.AdLoader.loadAd(params, options, listener)`（三参回调形式，元服务 SDK 无 Promise 重载，已封装为 Promise）+ `AdComponent` 展示（原生）；`AutoAdComponent`（Banner 自动请求/轮播/上报，最省事）
- **OAID**：~~`identifier.getOAID()`~~ ❌ **元服务禁用 identifier/OAID（编译器确认）→ 只能投放非个性化广告**（eCPM 低于个性化，但零权限成本，`module.json5` 无需声明 APP_TRACKING_CONSENT，隐私协议更好写）
- **测试广告位 ID**（华为官方，调测期用）：原生大图 `testu7m3hc4gvm`、原生视频 `testy63txaom86`、Banner `testw6vs28auh3`
- **硬约束**：
  - ⚠️ **模拟器不出广告，必须真机联调**
  - 用户同意隐私协议前不得请求/展示广告（首启弹隐私协议，同意后才初始化广告）
  - 原生广告每次曝光/点击都要正确上报（用 `AdComponent` 系统渲染则自动上报）
  - 禁止循环请求；`onError` 后除激励视频外不重试
  - 元服务禁止集成 so 文件 → Ads Kit 为系统 Kit 不含 so，✅ 无冲突；包体积影响可忽略
- **开关设计**：`AdIds.ets` 里加全局 `AD_ENABLED` 开关 + 测试/正式 ID 切换，审核或广告未过验时可一键关闭广告展示

## 9. 上传版本与提审流程（2026-08-11）

### 9.1 上传前确认

1. `AppScope/app.json5` 的 `versionCode` **每次上传必须递增**（当前 1000000 / 1.0.0）
2. **Build Mode 必须是 release**（DevEco 右下角状态栏或 Build → Build Mode 切换；debug 包带调试标记，AGC 直接拒收："当前Build Mode生成的包不可上传"）
3. 带广告的版本：正式广告位 ID 已替换、`USE_TEST_IDS = false`、`AD_ENABLED = true`（测试 ID 提审必挂）
4. 必须用**发布证书**签名（genfee.p12 + 发布 cer/p7b，别名 genfee），调试签名的包传不了

### 9.2 打发布包（本工程，DevEco Studio）

`Build → Generate Signed App` → 选 .app → 自动读取 build-profile.json5 的 release 签名 → 得到签名 .app 包（构建日志末尾有产物路径）

### 9.3 AGC 提审

1. AGC → 找到元服务（com.atomicservice.6917611690461753557）→ 版本管理 → 创建新版本
2. 上传 .app → 平台自动检测（包大小 ≤10MB、签名、bundleType、API Level、无 debug 标记）
3. 填资料：**ICP 备案号**、**隐私政策 URL**（含鸿蒙描述，权限仅 INTERNET）、服务类目（招聘求职，留意人力资源资质）、截图、版本说明
4. 提交审核（1~7 个工作日）

### 9.4 常见驳回预防

隐私政策权限不一致 / "功能过于简单"（应对：恢复地区选择页）/ 招聘类资质 / 广告违规（测试 ID 忘换、无关闭按钮、重复展示——本工程封装已规避）

## 10. 审核驳回整改记录（2026-08-18 首次驳回）

### 驳回 1：深色模式对比度不足（实测控件对比度 1.37）

**整改策略**：UI 为浅色硬编码设计，采用**强制浅色模式**彻底免疫，而非做深色适配：
- `EntryAbility.onCreate`：`setColorMode(COLOR_MODE_LIGHT)`（`@kit.AbilityKit` 的 `ConfigurationConstant`）

**同时加固前景色对比度**（审核已盯上对比度，浅色模式下也要过 3:1/4.5:1）：

| 原色 | 对比度(白底) | 改为 | 对比度 |
|---|---|---|---|
| `#FFC900`（立刻联系/薪酬/弹窗主按钮） | ~1.9 ❌ | `#A67C00` | ~3.8 ✅ |
| `#FDD000`（温馨提示文字） | ~1.4 ❌ | `#A67C00` | ~3.8 ✅ |
| `#FD7272`（列表薪资） | ~2.7 ❌ | `#D62828` | ~5.0 ✅ |
| `#FAC23C`（详情标签） | ~2.0 ❌ | `#A67C00` | ~3.8 ✅ |
| `#4D222222`（30% 灰） | ~1.9 ❌ | `#595959` | ~5.9 ✅ |
| `#80222222`（50% 灰） | ~2.9 ❌ | `#595959` | ~5.9 ✅ |
| `#888888`（弹窗次按钮） | ~3.9 ⚠️ | `#595959` | ~5.9 ✅ |

### 驳回 2：底部系统导航条未适配

- `EntryAbility`：读取 `AvoidAreaType.TYPE_NAVIGATION_INDICATOR` 的 `bottomRect.height` → 存 `AppStorage('navBarHeight')`
- 列表页：`List` 加 `padding({ bottom: navBarHeight })`——滚动内容可显示在导航条下方，滚到底最后一条不被遮挡
- 详情页：底部固定操作区 `padding bottom = 15 + navBarHeight`——按钮抬高，白色背景延伸进导航条区域形成沉浸融合；内容区 Scroll 底部留白同步 +navBarHeight
- 弹窗（隐私协议/拨号降级）：系统 `promptAction` 弹窗自动避让导航条，无需处理

### 教训（下次直接做进首版）

**沉浸式布局必须同时处理顶部状态栏和底部导航条两个避让区**；**文字前景色白底对比度 ≥4.5:1 作为硬指标**（浅金/浅灰是高危色）。
