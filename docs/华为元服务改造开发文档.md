## 1. 背景与目标

现有项目 `worker-bee-mini-program-1.0` 是一个基于 **uni-app（Vue 3，07-31 由 Vue 2 升级，见 §12）** 的工蜂元服务，目前已编译发布到 **微信小程序**（appid: `wx3d729ba6e18f2280`）和 **抖音小程序**（appid: `tt3d604bdda251d2d301`）。

**目标**：将该项目改造为可打包上架的 **华为鸿蒙元服务**（HarmonyOS Atomic Service，鸿蒙 Next 5.0+ 上的"小程序"），同时尽量不影响现有微信/抖音端的维护。

## 3. 技术方案选型

### 方案 A：uni-app 直接编译元服务（✅ 推荐）

DCloud 自 **HBuilderX 4.34** 起支持 uni-app 编译鸿蒙元服务（ASCF 技术方案），**Vue 2 / Vue 3 均支持**，HBuilderX 和 CLI 两种方式皆可。

- **优点**：复用现有 90%+ 代码；条件编译 `MP-HARMONY` 隔离平台差异；一套代码维护微信/抖音/元服务三端；本项目体量小（3k 行）、无 UTS 插件、无 plus API、静态资源 148KB，几乎是为元服务量身定做的体量。
- **缺点**：ASCF 方案不支持 UTS 插件与 ArkTS 原生写法；个别 API 差异需踩坑实测（如拨号）。

### 方案 B：DevEco Studio + ArkTS 原生重写

- **优点**：能力上限最高，可调用全部 HarmonyOS API。
- **缺点**：6 个页面 + 网络层 + 登录全部重写，工作量约是方案 A 的 3~5 倍；后续微信/元服务双端维护分裂。
- **结论**：本项目业务简单（列表 + 详情 + 登录 + 上传），无任何必须用原生能力的场景，**不建议**。

**选型结论：方案 A。** 若后续实测发现关键 API（如拨号）在 ASCF 下不可用且无替代，再评估局部回退。

## 4. 元服务平台硬约束（来自华为官方文档）

| 约束 | 要求 | 本项目评估 |
|---|---|---|
| 单包大小 | 单个 HAP（含依赖 HSP）≤ **2MB**，超限 DevEco 直接打包失败 | 当前资源 148KB，✅ 无风险 |
| 总包大小 | 所有包总和 ≤ **10MB**（可邮件申请放宽至 20MB） | ✅ 无风险 |
| 模型 | Stage 模型，`bundleType = atomicService`，单 Ability，分包仅支持 HSP | uni-app 模板自动满足 |
| 系统版本 | 仅支持鸿蒙 Next **5.0+**（4.x 及以下不可运行） | 目标用户需知悉 |
| API Level | ≥ 10 | 满足 |
| 登录规范 | **禁止自建登录页**，必须用 `uni.login` 华为账号登录；**必须提供账号注销入口**，否则审核驳回 | ⚠️ 需新增注销功能 |

| 发布区域 | 仅支持中国大陆 | 符合业务 |
| 平板/折叠屏 | 不能满屏（有黑边），华为 ASCF 规划如此，不影响审核 | 知悉即可 |

## 5. 改造清单（方案 A）

### 5.1 工程配置改造

1. **工具链升级**
   - HBuilderX 升级至 **4.51+**（建议最新 Alpha）
   - 安装 **DevEco Studio 5.1.1+**（HBuilderX 需调用其鸿蒙工具链；模拟器需 API 19+ 镜像）
   - 注册华为开发者账号 + 企业认证

2. **AGC 侧准备**
   - 在 AppGallery Connect 注册元服务，获得包名 `com.atomicservice.[APPID]`
   - **立即启动 ICP 备案**（周期长，是上架关键路径）
   - 配置 httpRequest 合法域名：`https://api.ggfee.cn`
   - 申请签名证书三件套（.p12 / .cer / .p7b），调试证书与发布证书分开

3. **manifest.json 增加 mp-harmony 配置**
   - 填写鸿蒙元服务包名
   - 首次运行生成 `harmony-configs/` 目录，配置权限：
     - `ohos.permission.INTERNET`（网络请求，必需）
     - 视实测结果决定是否申请其他权限（隐私协议须与权限严格一致，**能少申请就少申请**）

### 5.2 登录链路改造（核心）

**现状**：微信端走 `uni.login` 拿 code + `<button open-type="getPhoneNumber">` 拿加密手机号 → 后端 `/auth/login/wechat` 解密换 token。

**元服务目标链路**（机制高度相似，改动可控）：

```
uni.login({ provider: 'huawei' }) → 华为登录 code
  + <button open-type="getPhoneNumber"> → e.detail.code（手机号授权 code，非微信的 encrypted_data/iv）
  → 后端新端点 /auth/login/huawei → 返回 token + user
```

具体改动（`pages/my/index.vue`）：**（已实现）**
- 新增 `#ifdef MP-HARMONY` 分支：`uni.login({ provider: 'huawei' })` 拿登录 code，`getPhoneNumber` 回调拿 `e.detail.code`（手机号授权 code），调 `loginByHuawei({ code, phone_code })`
- 现有 `#ifdef MP-WEIXIN` / `MP-TOUTIAO` 分支原样保留，三端并存
- **新增"注销账号"入口**（华为审核硬性要求）：三端统一展示，弹确认 → 调 `deactivateUser` → 清除本地 token 与用户缓存

> ⚠️ **阻塞依赖**：后端需新增 `/auth/login/huawei` 端点（华为 code 换登录态 + 手机号授权 code 换手机号），以及注销账号接口。详见 §7。
> ⚠️ **权限申请**："获取手机号"属于华为**敏感权限**，需在 AGC 后台「API 服务 → 授权管理 → 敏感权限」申请，审核通过后才可调通，建议注册元服务后立即申请。

### 5.3 UI / 布局适配（已实现）

1. **自定义导航栏**：首页 / 我的 / 查看记录三页的自定义导航栏 `#ifdef MP-WEIXIN` 已扩展为 `#ifdef MP-WEIXIN || MP-HARMONY`。元服务不支持胶囊位置，直接复用 `beesys()` 的 `statusBarHeight` + 固定 `barHeight=38` 方案，`main.js` 无需改动（胶囊计算原本就只在 MP-ALIPAY 分支）。
2. **安全区/沉浸式**：真机跑通后按实际效果微调 `paddingTop`（待定）。
3. **图标**：按华为标准图标底板重新生成元服务图标（设计任务，上架前完成）。图标需放置于 `harmony-mp-configs/AppScope/resources/base/media/app_icon.png`，512×512。

## 7. 需要后端配合的事项

| # | 事项 | 说明 | 优先级 |
|---|---|---|---|
| 1 | 新增 `POST /auth/login/huawei` | 华为 code 换登录态 + 手机号解密，接口约定见 §7.1 | P0 阻塞 |
| 2 | 新增账号注销接口 | 华为审核硬性要求，需真正删除/匿名化用户数据，接口约定见 §7.1 | P0 |
| 3 | （可选）用户表增加 huawei_openid 字段 | 区分登录渠道 | P1 |

### 7.1 后端接口约定（提交后端排期用）

#### ① 华为登录：`POST /mini/auth/login/huawei`

**请求体**（与微信登录不同：华为两个环节给的都是 code，没有 encrypted_data/iv）：

```json
{
  "code": "string，uni.login({provider:'huawei'}) 获取的华为登录 code",
  "phone_code": "string，getPhoneNumber 按钮回调的 e.detail.code（手机号授权 code）"
}
```

**后端处理**：
1. 用 `code` 调华为 Account Kit 服务端「解析凭证」接口换取 `openid` / `unionid`（参考：华为 Account Kit 获取用户级凭证）；
2. 用 `phone_code` 换取用户级 access_token，再调华为「获取用户信息」接口拿到手机号（前提：AGC 已申请"获取手机号"敏感权限）；
3. 手机号已存在则登录，不存在则注册新用户（记录 `huawei_openid`）。

**响应**（与微信登录结构完全对齐，前端零改动复用）：

```json
{
  "code": 200,
  "data": {
    "token": "string",
    "user": {
      "id": 123,
      "avatar": "string",
      "nickname": "string",
      "is_realname_authenticated": true
    }
  }
}
```

#### ② 账号注销：`POST /mini/users/deactivate`

**请求**：Header 携带 `Authorization: {token}`，无请求体。

**后端处理**：删除或匿名化当前用户数据（手机号、身份证信息、头像昵称），使 token 失效；已发布的帖子按业务规则处理（建议随用户匿名化）。

**响应**：

```json
{ "code": 200, "msg": "注销成功" }
```

> 前端在注销成功后清除本地 token 及全部用户缓存，返回首页。
> 以上为建议约定，字段名可按后端习惯微调，保持响应结构与微信登录一致即可。

## 10. 联调与运行说明（M1 跑通步骤）

### 10.1 环境准备（一次性）

1. HBuilderX 升级至 **4.51+**，安装 **DevEco Studio 5.1.1+**；
2. 在 HBuilderX「工具 → 设置 → 运行配置」中配置 DevEco Studio 安装路径；
3. DevEco Studio 中下载 **API 19+ 模拟器镜像**（或准备鸿蒙 Next 真机，开开发者模式 + USB 调试）。

### 10.2 AGC 准备（一次性）

1. AppGallery Connect 注册元服务 → 得到包名 `com.atomicservice.[APPID]`；
2. **替换 manifest.json 中 `mp-harmony.bundleName` 的占位值**（当前为 `com.atomicservice.YOUR_APPID`）；
3. 配置 httpRequest 合法域名：`https://api.ggfee.cn`；
4. 申请调试证书三件套（.p12 / .cer / .p7b），注意**不能用自动签名**，否则登录/手机号调不通；
5. 在 AGC「API 服务 → 授权管理 → 敏感权限」申请**"获取手机号"权限**（需按场景详细填写，否则易被驳回）；
6. 在 AGC 项目「常规 → 应用」添加调试证书的**公钥指纹**；
7. 记录**应用级 Client ID**（注意是应用级，不是项目级）。

## 12. Vue 2 → Vue 3 迁移记录（2026-07-31）

### 12.1 起因

真机/构建时 HBuilderX 提示"vue 2 项目尚不支持鸿蒙平台"。核实官方口径：**鸿蒙应用（app-harmony）仅支持 Vue 3；鸿蒙元服务（mp-harmony）名义上支持 Vue 2，但编译器为 alpha 版本**。为彻底消除版本墙（两条产物线都通、后续恢复"我的"页等功能不踩 alpha 坑），决定将项目升级 Vue 3。Vue 3 兼容选项式 API，本项目无 filters / `.sync` / `$listeners` / `$set` / `slot-scope` 等 Vue2 专属语法（已全量 grep 确认），迁移面极小。

### 12.2 改动清单（3 处）

| 文件 | 改动 |
|---|---|
| `manifest.json` | `vueVersion: "2"` → `"3"`；同时清理 mp-harmony 占位包名，保留真实包名 `com.atomicservice.6917611690461753557`（distribute.bundleName） |
| `main.js` | `Vue.prototype.$beeMin` 包入 `#ifndef VUE3`；VUE3 分支改用 `app.config.globalProperties.$beeMin` 注册（beesys 为闭包引用，运行时已完成初始化） |
| `pages/index/index.vue` | 移除死代码：`liudx-pickerAddress` 组件的 import/注册/模板注释行及 `addresspick`/`addressShow`（该组件为 Vue2 `value`+`$emit('input')` 的 v-model 写法，Vue3 不兼容；地区选择早已由 region 页替代。组件源文件保留在 `components/` 未删，不进入打包） |

### 12.3 各端影响与回归要求

| 端 | 影响 | 回归项 |
|---|---|---|
| 元服务 | 解除版本墙，可正常走「运行/发行 → 鸿蒙元服务」 | 列表 → 详情 → 拨号 |
| 微信小程序 | Vue3 编译，选项式 API 平迁，理论上无行为变化 | **发版前必须冒烟**：首页列表/下拉/上拉、详情、地区选择、我的-微信登录、拨号、实名上传 |

## 14. 鲸鸿动能广告接入评估（2026-08-11）

### 14.1 结论（先说重要的）

**uni-app（ASCF）编译的元服务当前无法在代码中接入鲸鸿动能广告**：

| 证据 | 来源 |
|---|---|
| `uni.createRewardedVideoAd` 兼容性表中 HarmonyOS Next = ❌（仅 App/微信/QQ/抖音/快手支持） | uni-app 官方 API 文档 |
| "获取激励视频"被列为元服务**未实现 API**（调用报 `xxx is not defined`，官方建议条件编译规避）；Banner/插屏/ad 组件/uni-ad 均无支持说明 | uni-app mp-harmony 文档 |
| ASCF 不支持 UTS/ArkTS 原生写法，**没有绕行通道** | 同上 |

补充：ASCF 框架自身具备广告能力（华为侧资料），但 uni-app 编译层尚未暴露；华为原生 ArkTS 元服务可通过 **Ads Kit**（`@kit.AdsKit`）完整接入。

### 14.2 业务侧操作步骤（不依赖代码，现在就能办）

1. **主体准备**：华为开发者企业实名认证 → 开通商户服务 → 签署《鲸鸿动能媒体服务协议》
2. **创建媒体**：登录鲸鸿动能媒体服务平台（流量变现官网 →"开始变现"）→ 添加媒体。前提是在 AGC 已创建元服务并生成 APPID（我们已有 `com.atomicservice.6917611690461753557`，✅ 满足，无需等上架）
3. **创建展示位**：媒体管理 → 添加展示位，获取广告位 ID（调测可用测试 ID，如激励视频 `testx9dtjwj8hp`、Banner `testw6vs28auh3`）
4. **测试验证**：测试广告位 ID 真机调测（⚠️ 模拟器不支持广告，必须真机）→ 提交华为验收
5. **商业上线**：换正式广告位 ID，随元服务版本上架

合规要点：用户同意隐私协议前不得请求/展示广告；禁止定时器循环请求、禁止 onError 后立刻重试（激励视频仅可重试 1 次）；原生广告每次曝光/点击均需上报。

### 14.3 技术路线选择

| 路线 | 说明 | 建议 |
|---|---|---|
| **A. 首版不带广告先上架** | 业务侧 §14.2 先办；同时到 uni-app 鸿蒙化技术交流群确认 mp-harmony 广告 API 排期，DCloud 支持后接入只是填广告位 ID 的事 | ✅ 推荐 |
| B. 广告是首版刚需 | 只能放弃 uni-app 编译路线，ArkTS 原生重写元服务接 Ads Kit（即原方案 B，工作量 3~5 倍） | 不推荐首版这么做 |
| C. 广告放其他端 | 微信小程序流量主/抖音广告承载变现，元服务端先做获客与占坑 | 可并行 |

> 待验证项：ASCF 原生 DSL（不经 uni-app）是否暴露广告 API——若暴露，还存在"ASCF 原生工程重写"的中间路线，工程量介于 A/B 之间。需要时可向华为 ASCF 团队或开发者社区求证。
